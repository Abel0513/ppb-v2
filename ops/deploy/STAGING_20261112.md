## 安全暫存程式

`ops/deploy/stage-release.py` 為 **離線工具**。輸入固定版本包、完整 SHA256、Git commit、私人 staging root、正式站唯讀 root。它會：

1. 比對 SHA256；使用既有 `check-release.py` 檢查危險路徑、敏感資料、符號連結、大小上限與必要檔案。
2. 讀取 `.ppb-release.json`，確認 commit 等於核准版本；不接受含憑證、正式 `.env` 或 `storage/` 的版本包。
3. 先在 `/www/ppb-v2-deploy/releases/` 的 root 專用暫存目錄內逐檔安全寫入，完成後才改名為 `candidate-<commit前12碼>`；候選版本若存在則停止，不覆寫。
4. 與指定 live 目錄的**對應候選檔案**唯讀比較，輸出相同／差異／新檔的數量及至多 15 個檔名。**不判斷被刪除的舊檔案，也不宣稱已驗證應用可執行**。
5. 不複製、覆蓋或改動正式網站；不連線網路、DB、WP、LINE；不執行 Laravel、Composer 或 Migration；不更新 Nginx／Cron／IAM。

## 安全測試

`ops/deploy/tests/test_stage_release.py` 使用 temporary fixture，不連 AWS、資料庫，涵蓋成功解壓與正式檔案保持一致、不符 SHA、commit、既有候選目錄、非私有權限、live 路徑重疊、tar 路徑穿越、secret 路徑、tar symlink、staging-root symlink。

PR 會使用現有 GitHub Actions `PPB V2 offline release guard tests` 執行全部測試。**先等 CI 綠燈；合併本 PR 不會在 EC2 安裝或執行暫存程式**。
